ROADMAP EXECUTOR MINISHELL (sans bonus) - version avec heredoc + Ctrl-C explicite

Objectif global
- Coder un executor qui gere correctement :
  - commandes simples
  - builtins / externes
  - redirections < > >> <<
  - pipelines |
  - prefix assignments VAR=42
  - heredoc + interruption Ctrl-C
  - codes de retour (last_status / $? )
- Sans changer les structs de base (t_data, t_command, t_redir).

======================================================================
PHASE 0 - Contrat Parser -> Executor (a verrouiller)
======================================================================
But
- Pouvoir coder l'executor sans attendre que tout le parser soit fini.

Contrat minimal
- Pour chaque t_command :
  - argv est NULL-terminated
  - redirs est une liste chainee dans l'ordre d'apparition
  - redirs->target contient :
    - fichier pour < > >>
    - delimiteur pour << (ex: "EOF")
  - les erreurs de syntaxe sont deja filtrees (pipe mal place, redir sans cible, etc.)
- Pour heredoc, le parser met juste :
  - type = R_HEREDOC
  - target = "EOF" (le delimiteur)

Important
- L'executor prepare le contenu du heredoc.

======================================================================
PHASE 5B - Heredoc + Ctrl-C (phase dediee)
======================================================================
But
- Gerer proprement l'interruption pendant la saisie heredoc.

Comportement attendu (sans bonus)
- Si Ctrl-C pendant un heredoc :
  - interrompre la lecture du heredoc
  - abandonner la commande en cours (ne pas executer)
  - nettoyer les temp files / fd ouverts pour cette commande
  - revenir au prompt
  - data->last_status = 130

A prevoir
- Un moyen de remonter "heredoc interrompu" (flag / code de retour dedie)
- prepare_all_heredocs() doit remonter cet etat
- executor_run() doit stopper proprement si heredoc interrompu

Exemple de codes de retour (au choix)
- 0   = ok
- 1   = erreur
- 130 = interruption heredoc par Ctrl-C

======================================================================
PHASE 6 - Pipeline (|) sans redirs, puis avec redirs
======================================================================
But
- Executer plusieurs commandes en pipeline.

A coder
- exec_pipeline(t_data *data, t_command *cmds)
- alloc_pids()
- wait_all_and_get_last_status()

Logique (version de base)
Pour chaque commande :
- creer pipe (sauf derniere)
- fork
- child :
  - brancher stdin/stdout via pipe
  - builtin child ou execve
- parent :
  - fermer fd inutiles
  - stocker pid
  - garder read-end pour la suite

Puis integration redirs dans les childs
Ordre conseille dans child :
1. brancher les pipes (stdin/stdout par defaut)
2. apply_redirections(cmd) (les redirs peuvent ecraser le pipe pour ce flux)
3. exec builtin child / execve

Tests
- echo hi | cat
- env | grep PATH
- cat file | grep x | wc -l
- echo hi > out | cat   (stdout de echo va dans out, pipe vide)
- cat < in | grep a

PHASE 7 - Builtins dans pipeline vs parent (comportement final)
======================================================================

Regle finale
- Commande seule + builtin d'etat shell (cd, export, unset, exit) -> parent
- Builtin dans pipeline -> child (comme une commande normale)
  - les effets sur l'env du shell parent ne persistent pas (normal)

Tests cibles

- cd .. | cat              (ne doit pas changer le cwd du shell parent)
- export A=42
